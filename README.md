# 牛影随看

牛影随看是连接现有飞牛影视服务的原生 Android 客户端。应用以片库浏览、主动随看和本机连续观看为主线，使用原生登录、局域网发现、Media3 ExoPlayer 和单实例播放器。

## 当前入口

应用启动后进入片库，底部提供三个入口：

- **片库**：切换媒体库，按全部／电影／剧集查看已加载作品，搜索片名，应用筛选，打开作品详情。
- **随看**：用户主动开始一段观看队列。队列来自当前媒体库的服务端分页结果，会保存当前项并支持继续加载；它不是推荐系统，也不会自动播放陌生作品。
- **我的**：查看继续观看、稍后看、影片资料／刮削和连接设置。

片库卡片使用标题、类型和可用海报展示作品。海报是否完整取决于 NAS 返回字段、权限和图片请求；本轮没有把所有真实片库的海报展示当作已验收结果。

## 安装与首次登录

1. 在 Android 8.0（API 26）或以上设备安装 APK。
2. 让手机与 NAS 处于可互通的网络，启动应用并点击登录。
3. 登录页会尝试发现当前局域网影视库，也可以手动填写 IP、IP:端口或完整 HTTP/HTTPS 地址。省略端口时，裸主机名按 HTTP 5666 处理。
4. 输入飞牛影视用户名和密码完成登录。密码只在登录请求期间存在于内存，不保存到 Activity 状态或本地文件；会话令牌由 Android Keystore 保护。

应用不会把电脑浏览器的登录态自动迁移到手机。旧会话如果没有可确认的账号身份，会要求重新登录后再启用账号隔离的本机观看记录；这不会把旧位置静默写入未知账号。

## 从片库到播放

片库负责找内容，详情负责做播放决定。打开电影或剧集详情后可以：

- 查看已读取的标题、简介、年份、类型和海报字段；
- 对剧集切换季并选择具体分集；缺少第一集时提示用户手动选择，不会悄悄跳到第二集；
- 点击“稍后看”加入或移出本机列表；
- 点击播放或继续播放，进入唯一的播放器 Activity。

详情页不会直接解析播放 URL。客户端将选中的稳定媒体 ID、队列、队列位置、播放模式和同季连续播放选项封装为 `PlaybackRequest`，`MainActivity` 在进入前台后才解析当前媒体的播放源。这样返回片库、切换详情或冷启动片库都不会隐式创建播放任务。

播放器默认按源画面比例完整显示，可由用户主动切换铺满；保留暂停、进度拖动、倍速、音轨兼容回退和同季下一集提示等现有能力。网络响应必须仍属于当前媒体、服务器和请求代数，迟到结果不会抢播旧内容。

## 本机继续观看与稍后看

观看位置和稍后看只保存在本机，不写回飞牛影视服务端：

- 续播数据按规范化服务器地址、登录用户名和稳定媒体 ID 隔离；不会使用密码或令牌作为账号身份。
- 播放暂停、切后台、切集和退出时保存位置；完成态保留历史信息，但继续播放会从头开始。
- 详情页可以加入稍后看，“我的”页面可切换继续观看和稍后看列表。
- 旧版无账号位置只在首次识别到真实账号时懒迁移，旧键不会被删除；无法识别账号时要求重新登录，避免多个账号共享空命名空间。
- 索引损坏时会从本机记录回退，有限的展示快照不会删除较旧的可续播位置。

本机记录依赖服务器与账号身份。切换服务器、退出登录或使用没有账号身份的旧会话时，应用不会把上一个账号的私有片单展示给新账号。

## 影片资料／刮削

“我的”中的影片资料页是原生只读页面：它展示客户端已经读取到的资料、已检查数量和缺失字段，并可打开飞牛管理地址。客户端不会扫描 SMB、修改媒体文件、写入刮削结果或伪造服务端任务进度；资料不完整也不会阻止一个已有可播放源的条目进入播放。

手动匹配、候选确认、服务端写回和完整资料修正仍属于后续接口验证范围。当前页面的缺失数量只代表已经加载和检查的范围，不代表 NAS 全库统计。

## 当前边界

源码和 JVM 测试覆盖了页面状态、账号隔离、续播索引、稍后看、显式播放交接、请求代数和部分错误路径。以下项目仍需在目标 NAS、真实账号和实际 Android 设备上单独验收：

- 登录、局域网发现、覆盖安装和真实媒体播放；
- 海报请求、权限、不同片源解码、字幕、音轨和转码兼容性；
- 多季剧集、长目录、服务端分页边界及超过一页的完整目录；
- 横向拖动、上下滑、切后台恢复和单实例播放器的真实设备交互。

本轮不宣称全量多季目录或所有真实片库海报已经验收。应用不包含上传、删除、离线下载、云端推荐、公开分享、远程组网或新的 NAS 中转服务。

## 开发、构建与验证

构建要求为 Android SDK／Build Tools 35、JDK 17、Gradle 8.9、AGP 8.7.3 和 Media3 1.5.1。使用 Gradle Wrapper 执行：

```bash
./gradlew testDebugUnitTest lintDebug assembleDebug
```

Windows 也可以使用：

```powershell
.\tools\build.ps1 -Task testDebugUnitTest,assembleDebug,lintDebug
```

调试 APK 原始输出为 `app/build/outputs/apk/debug/app-debug.apk`；交付脚本会按 `versionName` 和 `versionCode` 导出带版本名的文件。每次交付 APK 都必须递增 `app/build.gradle` 中的 `versionCode` 并更新 `versionName`。

GitHub Actions 的构建检查与历史验收记录见 [Review delivery verification](docs/REVIEW_DELIVERY.md)。本地构建通过、JVM 测试通过或 APK 能安装，都不能替代真实设备登录和播放验收。

## 签名与覆盖升级

发布包使用固定的 PKCS12 签名身份和 alias `fnvideo`。PR 构建只用于测试和临时 APK，不保证可覆盖安装；可覆盖升级要求 `applicationId`、签名和递增的 `versionCode` 保持兼容。

签名密钥、密码和密钥库不得进入 Git、日志或 Actions artifact；不要为后续版本重新生成发布密钥。完整的签名、证书指纹、Secrets 和首次迁移边界见 [APK 签名与覆盖升级](docs/APK_SIGNING.md)。
